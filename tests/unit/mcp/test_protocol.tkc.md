Tests `core.mcp.protocol` by importing it (X7.2). The file it replaces declared its own `jsonrpcbuild`/`jsonrpcerror`/`validmethod` and asserted against them, so all of its coverage of the wire format was of a copy written twenty lines above the assertions. This module is the only JSON-RPC serialiser in the tree and two live callers pass a tool's whole output through it (`packages/mcp-toke/src/tools.tk`, `packages/core/src/memory/mcp_server.tk`). Covers: the JSON-RPC 2.0 envelope on both success and error (version, id echo, verbatim result embedding, mutual exclusion of `result` and `error`); tool results including the `isError` flag; `tools/list` for zero, one and two tools — the two-tool case is what catches a comma-separator bug that would make every tool after the first invisible; `initialize` advertising protocol version `2024-11-05` and the tools capability; and request field extraction through `buildrequestfromobj`. Every envelope is parsed with `json.dec` as well as inspected with `str.contains`, and the validity helper is itself asserted in both directions so the parse checks cannot be vacuous. **`parserequest` is deliberately not called**: `mt` binds its arms BY POSITION, not by tag (measured — the T-18 family, stated more sharply), and `protocol.tk:52` writes `$jsonerr` first, so it returns `$err` for every valid request and runs `buildrequestfromobj` over the error payload for an invalid one; calling it would segfault rather than fail an assertion. **Carries two deliberately failing assertions**: `errorresponse` does not escape its message at all, so a double quote in it breaks the envelope (live: `tools.tk:312` builds one from a client-supplied tool name); and `buildrequestfromobj` sets `paramsraw` with `json.enc(json.getval(...))`, passing a Json handle where a `str` is declared, so it renders the POINTER — measured as `"51887746848"` — meaning no MCP tool can ever receive an argument. Depends on `std.test`, `std.str`, `std.json`, `core.mcp.protocol`.
