Tests `core.models.registry` by importing it (X7.2), with `shared.types` for `$tasktype`, `$modeltier` and `$provider`. The file it replaces declared its own model table and selection function, and so could reach none of the three defects the module's own comments record: `findfortask` returned an **empty array for every task** because `let matches=matches.append(entry)` declared a new binding; `bestfortask` selected nothing at all (a type sigil on a local, two shadowing `let`s) and took the *first* acceptable candidate rather than the best; and `findbest` returns a result whose error arm T-18 makes dead, where reading any field off the mis-bound value **segfaults**, which is why `core.router.router.route` crashed unconditionally. The result-returning `findbest` and `byid` are deliberately not called; the plain `bestfortask` and `capabilitybyid` exist precisely so they need not be. Covers: the registry is populated; the `nocapability`/`iscapability` sentinel; `findfortask` returning real matches and actually filtering by task; **`localonly` as a privacy filter** — asserted over *every* entry returned, not a sample, because one hosted entry leaking through would route a sensitive prompt off-device; `meetstier`'s speed floors including both strict boundaries (exactly 40 and exactly 8 must fail, which matters because qwen2.5:72b runs at exactly 8.0); `bestfortask` picking the best rather than the first, and the tier floor forcing a real trade of quality for latency (interactive local chat falls from qwen2.5:72b at 0.88/8 tok/s to qwen2.5:7b at 0.72/45 tok/s); the sentinel when nothing qualifies; `capabilitybyid`; and `register` adding an entry while leaving the registry it was given alone, since toke structs are values. **Carries a documented finding that is deliberately not asserted**: `meetstier` **SEGFAULTS on the `$background` tier** — `$interactive` and `$considered` return normally, `$background` faults at any speed, and so does `reg.bestfortask(r;$chat(0);false;$background(0))`, because `bestfortask` calls `meetstier` once per candidate. The match is three arms whose first two return a comparison and whose third returns a literal `true`; only the third faults, placing it in the T-2 family (toke miscompiling a match of three or more arms) rather than in anything about the tier's meaning. The consequence is that **model selection at the background tier crashes**, which is the whole overnight/agent path. Verified on a freshly rebuilt object archive, because a partial archive can fake a crash. Depends on `std.test`, `std.str`, `shared.types`, `core.models.registry`.
