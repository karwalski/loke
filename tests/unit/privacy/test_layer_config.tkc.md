Tests `core.privacy.layerconfig` (F3b.2), which reads `[[privacy.layers]]` entries from a config.toml text and applies them to `core.privacy.filterregistry`. Covers: no entry leaves the registry in its default order with every layer detect-and-mask, threshold 0 and no entity filter (so the default accepts every detection); `priority` reorders the registry (lower first, equal priorities keep registry order, negatives, two entries); `enabled`, `mode`, `confidence_threshold` (as a number or as text) and `entity_filter` reach their entry, with comments, single quotes and a trailing comma; `accepted` drops detections below the threshold (a detection at it is kept) or outside the filter, `vetoes` and `masks` per mode. The regex layer: `enabled = false`, `detect-only`, a threshold and an entity filter are not applied and are named in the warning, while its priority and `veto` are. Malformed entries (unknown id or key, missing or unquoted id, a duplicate layer or key, wrong value kinds, a threshold outside 0..1 or with trailing text, an unknown mode or entity type, a multi-line or non-array filter, a line with no value, `[privacy.layers]` as a table, `layers` inline) each return an error and the registry unchanged, including a valid entry before the bad one. Depends on `std.test`, `std.str`, `shared.types`, `core.privacy.filterregistry`, `core.privacy.layerconfig`.
