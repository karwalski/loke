Tests `core.privacy.layerconfig` by importing it (X7.2); it previously declared its own `$layerentry`. Covers the default layer set and, specifically, **which layers ship enabled**, since that is the security posture of a fresh install: regex enabled (in-process, the one layer that cannot be unavailable), NER enabled, Presidio disabled because it needs a sidecar that is not part of the install — and that `enabledlayers` is therefore two and never zero. Also covers priority ordering (regex before NER before Presidio, deterministic and free first), `mode` — `detect-and-mask` actually redacts while `detect-only` reports and does not, so a layer silently switched to detect-only would look like a working pipeline and forward the text in the clear — confidence thresholds asserted at both ends rather than by exact value (zero would accept every candidate, one would accept none), the empty default entity filter, and `consensusstrategy` being `most-restrictive`, the fail-safe direction for redaction. **Records one finding**: `getlayer` seeds its accumulator with `layers.get(0)` and only overwrites on a match, so an UNKNOWN layer id returns the **regex layer's** entry — `enabled:true`, threshold 0.8 — under a name that does not exist. A caller asking whether a layer it has never heard of is enabled is told yes, and a diagnostic printed from it would be confidently wrong about which layer is doing what. Not fixed: the module has no importer anywhere, so the defect is latent; the assertion records it and turns RED when a sentinel or a `has` predicate is added. Depends on `std.test`, `std.str`, `core.privacy.layerconfig`.
