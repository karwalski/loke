Tests `core.privacy.layerhealth` by importing it (X7.2); it previously declared its own `$layerstatus` and `$healthreport`. **Records two findings rather than asserting correctness.** (1) `checkhealth` PROBES NOTHING: its entire logic is `if(str.eq(id;"presidio")){isavail=false}`, so every other layer id is reported available with reason "operational" whatever is running — NER reports healthy with no Ollama, Presidio reports missing on a machine where it is running, and a layer id naming nothing at all reports available. The report is fabricated in both directions, which is the class of defect NC1.9 exists to remove elsewhere in the privacy code. (2) An EMPTY layer list reports HEALTHY: `degraded` is `availablelayers<totallayers`, which for an empty list is `0<0` = false, so `formathealthstatus` says "HEALTHY: all 0 layers available" while `issystemhealthy` on the same report says false — two readers of one report disagreeing about whether no layers at all is healthy, and the one a human reads is the one that says yes. Neither is fixed here: the module has **no caller anywhere** (`core.privacy.pipeline` counts `layerscompleted` itself), so both are latent. Following the precedent in `tests/unit/storage/test_backup.tk`, the assertions record the behaviour as it is and turn RED when a real probe is added — which is the signal to rewrite them. Everything a real probe would need is exercised: report shape, per-layer id and non-blank reason, the available/total ratio, the `degraded` flag, both summary strings, and the only-Presidio case in which the module does report the system unhealthy — the fail-closed signal that nothing scanned the text. Depends on `std.test`, `std.str`, `core.privacy.layerhealth`.
