Tests `core.privacy.template` by importing it (X7.2); it previously declared its own template struct and renderer. Belongs in `privacy/` because each built-in template's system prompt constrains what the model may ask for, and the data-analysis one carries the sentence that makes the no-custody path (NC1) a path rather than a hope — "Never request raw data — work only with the schema and statistics provided". A template that lost it would still render, still send, and still look correct, so that sentence is asserted directly, as is the classify template's constraint to reply with only a category name. Also covers the five built-in ids (including that the American spelling `summarize` is *not* one), every built-in passing its own validator, each carrying a system prompt, user template and version, rendering substituting supplied parameters and leaving no placeholder behind, the system prompt SURVIVING rendering so the constraint is not dropped on the way to the provider, a missing required parameter reported through `missingparams` with its placeholder left visibly unsubstituted, an optional parameter falling back to its declared default and *not* being reported missing, and `validate` catching an empty id, an empty user template and an unclosed `{{`. **T-18 bounds what is testable**: `find` and `render` both return `X!$lokeerr` and toke takes the first arm whatever the value is, so `find(templates;"no-such-id")` binds the error payload as a `$prompttemplate` and reading a field off it SEGFAULTS — there is no way to assert the not-found path, and this file does not try. **Records a SEGFAULT finding, reported not fixed**: `renderuser(t;"{}")`, `renderuser(t;"")` and `render(t;"")` each crash the process (SIGSEGV), each reproduced in a file of its own, while `renderuser` with at least one key and `render` with `"{}"` are correct. The cause is T-18 again — both open with `mt json.dec(paramsjson) { $ok:obj obj; … }`, so a failed decode binds the error payload and is then used as a JSON object. `""` and `"{}"` are exactly what a caller sends for a template whose parameters are all optional, and what a UI submits before the user has typed anything; the crash takes the whole process, so in a server it is a denial of service reachable from a parameterless render. **No assertion is left in the honest direction for those three, deliberately**: a SIGSEGV aborts the binary, so one red assertion would destroy the other forty in this file and report nothing. The `validate` checks run from their own function because inlining them crashed the binary at the first `$prompttemplate` construction after the thirty-fifth assertion — a context-dependent miscompilation that disappears in a smaller function, and the reason `validate`'s empty-param-name check has no assertion. Depends on `std.test`, `std.str`, `core.privacy.template`.
