Tests `core.privacy.regex` by importing it — **story X7.5**, the sharpest single example in epic X7. The file it replaces imported `std.test` and `std.str` and nothing else: all fourteen assertions were `str.len` or `str.contains` over a *literal*, e.g. `str.len("123456789")==9` under the name `test_regex_detector`. It passed whatever the detector did, and it was green throughout the life and fix of PL1.10, in which an unanchored `patautfn` matched the trailing nine digits of every Australian mobile so every AU mobile was also reported as a tax file number — escalating the prompt from CONFIDENTIAL to RESTRICTED and so changing which providers it could reach. Deliberately does **not** repeat `tests/unit/privacy/test_regex_spans.tk`, which covers spans, the PL1.10 digit-boundary rejection and detection of email/phone_au/au_tfn/api_key. Covers instead: the PATTERN INVENTORY (ten patterns, each declared exactly once, none with an empty expression — an empty expression matches nothing and is a silent hole); the sensitivity each type carries, which `detect` maximises over and which decides the route and the gate; confidence ordering; detection of the types `test_regex_spans` never touches (credit_card, ip_v4, ssn_us, au_abn, url); the NEGATIVE cases — ordinary prose yields no entities and stays PUBLIC, a hyphenated word is not an email, four digits is not a card or a TFN or an SSN; and `detectwithpatterns` against a narrowed subset, which is how a caller disables an entity type and is untested anywhere else. Note `shared.types.senslabel` returns lowercase labels. Depends on `std.test`, `std.str`, `shared.types`, `core.privacy.regex`.
