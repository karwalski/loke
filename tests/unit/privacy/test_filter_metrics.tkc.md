Tests `core.privacy.filtermetrics` by importing it (X7.2); it previously declared its own `$layermetric`. Covers a fresh metric starting at zero (a counter starting anywhere else would over-report from the first request), accumulation ADDING rather than replacing, the returned value being the one that carries the update — these are value types, so a caller that drops the return records nothing, the same defect shape as `core.privacy.placeholder.addentry` (LS1.1a) and `core.storage.ephemeral.put` — and that a scan finding nothing still records its TIME, so a slow layer that finds nothing stays visible. **Records two findings.** (1) `avgconfidence` IS NOT AN AVERAGE: `recorddetection` assigns `avgconfidence:confidence`, overwriting with the most recent value, and there is no sample count to divide by. After 0.95, 0.80 and 0.0 a field named *avg* reads 0.0 rather than 0.583. A metric named avg that reports last is worse than none, because it will be quoted as an average and `docs/metrics-baseline.md` is the only place this project publishes figures from. (2) `entitycounts` IS NEVER WRITTEN: `newmetric` sets it to the literal `"{}"` and `recorddetection` copies it across unchanged, so the per-type breakdown the field exists for is permanently empty. Neither is fixed: the module has no importer anywhere, so no published figure comes from it. Following the precedent in `tests/unit/storage/test_backup.tk` the assertions record the behaviour as it is and turn RED when the average and the breakdown are implemented. Depends on `std.test`, `std.str`, `core.privacy.filtermetrics`.
