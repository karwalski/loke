Tests `core.privacy.content` by importing it (X7.2); it previously declared its own extractor and scorer. `extract` decides WHAT TEXT of a web page is handed to the privacy pipeline and then to a model: anything it fails to strip is forwarded, anything it strips is never scanned, and both directions are privacy-relevant. The load-bearing assertion is the first of those — a page's inline `<script>` routinely carries session tokens, API keys and embedded JSON about the logged-in user, none of it visible text, so a user reviewing what loke is about to send would never see it. The fixture carries `var apiToken="sk-ant-do-not-send-this"` in a script and a `.secretcss` rule in a style block, and the test asserts that neither survives into `.text`, that no markup or attribute name does either, and — as the control that makes those negatives meaningful — that the visible heading and paragraph do. Also covers link and form counts; both flags trigger by trigger (`haslogin` via a password input, "sign in" and "log in"; `haspayment` via "credit card", "checkout", "billing" and "CVV", case-insensitively) since a page that quietly stopped being flagged would score twenty points higher for no visible reason; the score's exact deductions and its lower bound; and the summary naming the HOST but not the PATH, which is itself information about what the user was doing, plus carrying no flag at all for an ordinary page — warnings must be earned. Records that the form penalty is `(formcount/10)*5` in integer arithmetic and so is a step at every tenth form rather than a slope, which is invisible from the formula's intent. Scope note: the module has no importer anywhere; `src/browser/workspace/extractor.tk` is a separate implementation, so a passing test here is not evidence that page extraction is covered on the live path. Depends on `std.test`, `std.str`, `core.privacy.content`.
