Tests `core.privacy.orgpolicy` by importing it and writing real policy files to disk under `~/.loke/test-org-policy` (X7.2); it previously declared its own policy struct and validator and asserted against them seventeen times. Covers the default policy being unenforced (a default that enforced something would apply an organisational control to every personal install) while still requiring at least one active layer, and `validate`'s two working checks — the minimum-layer count, with zero layers a violation, and the locked consensus strategy — including that two violations are both reported rather than only the first. **Records four findings in an ENFORCEMENT module.** (1) `minimum_layers` IS NOT PARSED: `let ml=mut.1; if(str.len(minlayers)>0){ml=2}` yields the literal 2 for any non-empty value, so an organisation requiring five layers gets a policy requiring two and a three-layer configuration validates clean — fail-OPEN on the one number the file exists to state. (2) `enforced` IS A SUBSTRING SEARCH over the whole file, so `{"enforced": false}` loads as enforced **true**, and the word appearing in an unrelated string turns enforcement on. (3) `max_confidence_threshold` is never read; it is hardcoded 1.0 in both `defaultpolicy` and `loadpolicy`, so the field is inert. (4) `validate` IGNORES `requiredlayers` and `bannedlayers` entirely, so a configuration running a BANNED layer validates with no violation — likely the very check an organisation wrote a policy file for. Also covers the one thing the loader gets right in the safe direction: a missing or trivially short file falls back to the unenforced default rather than to a policy that permits everything. None is fixed: the module has no importer anywhere, so no organisation's policy is being mis-enforced today; each assertion turns RED when the corresponding field is actually parsed or checked. Depends on `std.test`, `std.str`, `std.file`, `std`, `core.privacy.orgpolicy`.
