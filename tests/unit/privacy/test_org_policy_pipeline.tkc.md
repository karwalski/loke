Tests the organisation policy (F3b.8) through the production `core.privacy.pipeline.runforward`, with `scripts/lib/http_recorder.py` standing in for NER, Presidio and the privacy-filter sidecar and port 9 as a layer that is down. No policy file masks byte for byte what the pipeline masks with no policy at all (anonymised text with placeholders put back as type and position, every entity and consensus record); so do `enforced: false` and `{}`. `required_layers` refuses, naming the layer and the policy, when the layer is down, switched off in config.toml, off by default (the privacy filter) or detect-only, and raises a governance alert; `minimum_layers` refuses when fewer masking layers completed; a banned layer is sent nothing and config.toml enabling it, even explicitly, refuses; `locked_consensus` raises `unanimous` to `most-restrictive`, masking the name and email, and the run, the reply's consensus object (`configured_strategy`, `raised_by`) and `org_policy_overrides` record it, with an alert; `max_confidence_threshold` clamps layer thresholds and the privacy-filter threshold sent to the sidecar, so more is masked. A malformed, non-JSON or unreadable policy refuses clean text; the file is read at run time, also through `pl.configured`; the system-prompt path keeps the refusal. Under every policy field and five user configurations, each run is refused or masks every value the user's configuration masks. loke.log holds no text. Depends on `std.test`, `std.str`, `std.file`, `std.process`, `shared.log`, `core.privacy.pipeline`, `core.privacy.systemprompt`, `core.privacy.orgpolicy`, `core.privacy.filtermetrics`, `shared.config`, `shared.types`, `core.privacy.consensus`.
