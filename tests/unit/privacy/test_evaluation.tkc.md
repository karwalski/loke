Tests `core.privacy.evaluation` by importing it (X7.2); it previously declared its own precision/recall arithmetic. This module is the INSTRUMENT behind the recall and precision figures AD1.2 is measured with, and `docs/metrics-baseline.md` is the only place this project publishes numbers from — so what is asserted is not that the formulae are the textbook ones (a tautology against a copy) but that the instrument DISCRIMINATES and that its edge cases do not manufacture a flattering figure: a zero denominator yields 0 rather than 100%, a detector that detected nothing scores zero precision rather than perfect, F1 is the harmonic mean so 100% precision with 10% recall scores below 30% where an arithmetic mean would flatter it to 55%, and the false-positive and false-negative counts clamp at zero rather than going negative and producing a ratio above 100%. **Every assertion uses the basis-point functions, and that is forced rather than chosen**: `computeprecision`, `computerecall` and `computef1` return a BARE f64, which is corrupted across a module boundary (T-20, measured — `f64abs(-50.0)` arrives as the bit pattern 1), so they cannot be asserted from a test at all and a test that appeared to do so would be reading the wrong register. An f64 STRUCT FIELD crosses intact, which is why `$evaluationresult`'s `precision`/`recall`/`f1` can be read. Also covers `bplabel`'s zero-padded rendering (9505 bp is 95.05%, not 95.5%), `evaluatelayer` and `evaluatelayerbp` agreeing on the integer counts so two figures are not in circulation for one corpus run, and `newmatrix`/`addlayer` — declared when the module was written and never constructed, which AD1.2 records as most of why per-layer comparison could not be measured — including that `addlayer` returns the new matrix and leaves the caller's alone (LS1.1a's defect class). Scope note: the module has no importer anywhere, so exercising the instrument is not evidence that any published figure came from it. Depends on `std.test`, `std.str`, `core.privacy.evaluation`.
