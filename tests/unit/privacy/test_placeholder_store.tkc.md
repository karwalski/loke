Tests `core.privacy.placeholderstore` — the X8.2 sealed mapping table — by importing it (X7.2). The file it replaces declared its own `$store` with `newstore`/`addentry`/`getoriginal`/`restoreall` and asserted an in-memory association list: eighteen assertions, none touching the module. The table it is named for is the one `docs/threat-model.md:181` rates **Maximum**, above the audit log and above the prompt cache — a detector that misses an entity leaks one value, a readable mapping table leaks every value loke has ever detected and which request each belonged to — and for the whole period that table was plaintext on disk this file asserted that a nine-line function three lines above it returned what it had just been given. Written against the PRAGMA key lesson: plain SQLite accepts that pragma, ignores it and reports success, so a control reporting success is not evidence of a control. The load-bearing assertions are therefore **not** the round trip (which passes identically with no encryption at all) but: the sealed bytes do not contain the email, the name, the phone number, the placeholder, or even the entity type — each checked against `hexof` of the value, the module's own encoder, with a control assertion that the *unsealed* payload does contain them so the five negatives are not passing on an empty string; a fresh nonce and fresh ciphertext on every seal, so identical mappings are not recognisable as identical on disk; the AAD binding a ciphertext to its request id and key version, so a payload moved to another request's row will not open; refusal under a wrong key, an altered hex digit, an altered nonce, a truncated payload, and one seal's nonce with another's ciphertext; and 256-byte padding, so the stored size does not disclose how many identifiers a prompt contained. Also covers `derivemapkey` yielding *no* key rather than a short one for an unusable secret; the hex codec round-tripping a value containing `|` and a newline; `decodepayload` refusing an unknown version and failing the *whole* mapping on a malformed record (the payload is parsed only after the tag verifies, so a bad line is a codec defect, not tampering, and skipping it would give a silently shorter mapping); persistence, including that re-storing replaces the row rather than reusing a nonce, that a request id or a key it cannot seal under is refused with no row written, and that the entry count is unreadable without the key; restoration **failing closed** by leaving the placeholder visible rather than substituting a wrong name; and that `mappingencryptionstatus` names one table and does not imply `loke.db` is encrypted. Takes the secret as a parameter (X8.3), so it never touches the keychain and cannot block on an authorisation dialog. Depends on `std.test`, `std.str`, `std.file`, `std`, `core.storage.db`, `core.privacy.placeholder`, `core.privacy.placeholderstore`.
