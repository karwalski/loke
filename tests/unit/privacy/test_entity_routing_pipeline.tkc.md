Tests `[[privacy.entity_routing]]` (F3b.5) through the production `core.privacy.pipeline.runforward`, with `scripts/lib/http_recorder.py` standing in for NER and Presidio (both report "Jane Citizen" as PERSON; only the regex layer finds the card and the email). Proves no routing is byte-for-byte unchanged: an empty config.toml, one with settings and `[[privacy.layers]]` but no routes, and one on disk with no routes each give the same anonymised text (each salted placeholder put back as its type and position), the same entities (type, value, span, confidence, in order) and the same consensus records as the pipeline built without reading config. Judges routing by the layers each masked value is credited to: preferred Presidio or NER alone; the fallback when the preferred sidecar is off, when Presidio is switched off in `[[privacy.layers]]`, and when Presidio is down; every layer that ran when neither is available. The regex guard: a CREDIT_CARD route to Presidio, which finds no card, still masks the card, byte for byte as without routing. A malformed route refuses the run, even with no PII, naming line 4 and no PII, and applies nothing; a malformed `[[privacy.layers]]` beside it is the error reported. Through `pl.configured`, config.toml on disk is read. Depends on `std.test`, `std.str`, `std.file`, `std.process`, `core.privacy.pipeline`, `shared.config`, `shared.types`.
