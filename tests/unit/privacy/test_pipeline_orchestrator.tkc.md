Tests `core.privacy.pipeline`'s orchestration surface by importing it (X7.2). The file it replaces declared its own orchestrator; the giveaway was `classifysensitivity`, which returned CRITICAL when the prompt contained the English words "credit card" and HIGH when it contained an at-sign. The module has no such function, has no "critical" level (the four are public, internal, confidential, restricted) and classifies on detected entities rather than vocabulary — so all fifteen assertions described a design that has never existed. Deliberately does not repeat `test_fail_closed.tk` (the layer-count refusal) or `test_pipeline_full.tk` (anonymisetext, maxsensitivity, dedup). Covers: `newconfig`'s defaults, including that both optional layers default ON — a disabled layer is not a degraded layer and raises no diagnostic — and that `dryrun` defaults off; `ishighersensitivity` in both directions and specifically the `(internal, public)` pair, which the old chain of `==` on a sum answered false for, so `maxsensitivity` never escalated and a prompt full of card numbers computed as PUBLIC; `seenvalue`; `strictlyshadows`/`shadowedbyany`, including that a SPANLESS entity neither shadows nor is shadowed, which is what made this predicate useless for every regex-layer entity before PL1.7; `countrestricted` and `countconfidential` across **both** detection vocabularies, lowercase `credit_card`/`email` from the regex layer and SCREAMING_SNAKE `CREDIT_CARD`/`EMAIL_ADDRESS` from Presidio, since a counter that knew only one would report "0 RESTRICTED" for a card found by the other layer (the naming split is X7.6); `pipelinenerskip` reporting itself skipped with a reason, so a missing scan is distinguishable from a scan that found nothing (NC1.9); `run` end to end on both dirty and clean text, asserting layers completed, degraded count, maximum sensitivity, request id, and that the email is absent from the anonymised text; `summariserun` in **both** branches — its label was declared with a `let` inside the `if`, creating a branch-local binding, so it always read "Anonymised." including for a run that detected nothing; and `rundry` still completing a scan. Presidio and NER point at unprivileged ports nothing listens on, so only the in-process regex layer is live and no assertion waits on a network timeout. **Records a finding**: `applypreset`, `setentityenabled` and `setlayerenabled` (`pipeline.tk:727,731,735`) ignore every argument but the first and return it unchanged — complete no-ops with no caller anywhere, so a privacy-settings screen wired to them would report success and change nothing. Following the precedent in `tests/unit/storage/test_backup.tk`, the assertions record the no-op contract so that implementing them turns these RED.
