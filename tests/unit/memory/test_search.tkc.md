Tests `core.memory.search` by importing it (X7.2). The file it replaces declared a `$searchindex` with its own `addentry`/`scorematch`/`search`, scoring by word-overlap ratio; the real module extracts keywords, queries `memory_index` with LIKE, SUMs per-keyword weights per drawer and joins back to `memory_drawers` for the excerpt, so ten assertions passed against a design the product does not have. Covers two halves. THE PURE HALF decides which words are searched for — a keyword dropped here makes a memory unfindable, which the user experiences as the palace forgetting something it still holds: the stopword list is populated and catches long words like `would`/`should` that survive the length filter; extraction lowercases, keeps four-character words and drops three-character ones (the exact boundary), drops stopwords, and yields nothing for an all-stopword or empty query; `firstn` takes the first n, CLAMPS when n exceeds the length rather than reading past the end, returns nothing for n=0, and preserves order. THE SQL HALF is exercised against `memory_index` and `memory_drawers` that **this file creates itself**, because nothing in the product creates them (M1.7 — see `test_palace_drawers.tk`) and `palace.open` segfaults, so the module's own opener cannot either; that tests the module's query and scoring behaviour, which is real, and is NOT evidence that the product's schema exists. It covers multi-drawer and single-drawer hits, the excerpt and palace location proving the join back ran, the limit being honoured, a non-matching and an all-stopword query returning nothing rather than everything, `searchinwing` scoping correctly and excluding other wings, and — the LS1.1a regression — a drawer matching TWO keywords outranking one matching one, which confirms the per-keyword weights now accumulate. `indexdrawer` is NOT called: its signature takes `drawer:i64` while its body reads `drawer.content` and `drawer.id`, which segfaults, and it returns from inside its own loop so it would index one keyword per drawer and stop; rows are inserted with SQL for that reason.
