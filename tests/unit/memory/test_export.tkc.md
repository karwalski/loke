Tests `core.memory.export` by importing it (X7.2). The file it replaces declared its own `exportjsonentry`/`exportcsventry`/`exportfilename`/`validformat`/`countexportable` and asserted against them — including `countexportable()` returning the constant 42 and then asserting it equals 42, and asserting that `"txt"` is a valid export format when the real module supports json, csv and MARKDOWN and has never had txt. Export is the one place the product writes memory content OUT, and memory content is the most PII-dense data it holds, so an export that truncates or produces a file no importer can read loses the user's data at the moment they were trying to take it with them. Covers the pure half — `csvescape` (RFC 4180: wrap in quotes, double an interior quote, an empty value becomes a quote pair so a column cannot vanish, a comma preserved inside the quotes), `formatlabel` for all three real formats, and `formatmemorymd` (id heading, content, tags, labelled metadata, trailing rule) — and the row half against `memory_drawers` and `memory_scores` that **this file creates itself**, because nothing in the product creates them (M1.7). The row half exercises `buildcontentjson`, `buildcontentcsv`, `buildcontentmd` and the `buildcontent` dispatch over real `$row` values from the same query `exportall` issues, including tags arriving from the joined `memory_scores` row so the LEFT JOIN is shown to be read. **A memory containing a double quote**: the JSON export of it is asserted to be valid JSON, and the CSV export of the same row to double the quote, which is CSV's rule. This was written as a red finding and has passed since M1.7 (2026-09-23) fixed it: `rowtojson` had quoted every string with `csvescape`, which DOUBLES an interior quote, so `"content":"he said ""hi"""` ended the JSON string early and the file was unparseable. `rowtojson` now escapes through `shared.jsonobj.escape` (F10.47 removed the local wrapper) and `csvescape` is used only by `rowtocsv2`, where it is right. Depends on `std.test`, `std.str`, `std.file`, `std`, `std.db`, `std.json`, `core.storage.db`, `core.memory.export`.
