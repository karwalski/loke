MK6.10 — mcp-toke's anonymise, analyse and profile tools through `handletool`, as the server and moke's MCP panel call them. The input is synthetic text with a newline, a tab, quotes, an email address, an Australian phone number and a card number; the Presidio and NER layers are pointed at loopback ports nothing listens on. anonymise must answer the anonymised text with placeholders, the count (3), RESTRICTED, one layer completed and two degraded, keep the newline and tab (T-47: they arrived as the letters n and t), be strict JSON (validated by Python's json module through std.process, since json.dec accepts a raw newline, T-51), and hold none of the personal values or an `original` field; the positive control is that the same byte scan finds every value in the input. What the call adds to `shared.log`'s file must hold its count line (control), no personal value and none of the text. anonymise without text is refused. analyse must count the three, say not safe to send, give each entity as type and offsets with no value, and be strict JSON. profile must answer the schema (dataset name quoted once), the row and column counts and the PII hint with no value from the data, strict JSON; it refuses text that is not JSON, an object, and an array whose rows are not objects, each named (T-18: these went on with an error bound as the profile), and profiles `[]` as no data. Mutants, each restored and checked with `cmp`: `original` restored (2 assertions), the text logged (1; shared.log's sanitiser redacts the detected values, so only the text scan catches it), `json.str` for the argument (2), quote-only escaping (3), entity values restored (2), profile back on the `$datasetprofile!$lokeerr` match (SIGSEGV). Depends on `std.test`, `std.str`, `std.file`, `std.process`, `shared.log`, `core.mcp.protocol`, `mcptoke.tools`.
