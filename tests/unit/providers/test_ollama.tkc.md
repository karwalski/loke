Tests `core.providers.ollamaprovider` by importing it (X7.2), with `core.providers.types` for `$completionresponse`. The file it replaces declared its own chat-request builder and response extractor, and so could not have found LS1.1j — `complete` matched `ollama.sendchat`, a `str!$lokeerr`, with the error arm FIRST, and T-18 takes the first arm whatever the value is, so it returned `$err("chat call failed")` for **every** ollama and local dispatch including the successful ones. That matters more here than for the hosted providers: loke prefers the local model for anything sensitive, so the preference the product is built around could not be honoured and the fallback was a hosted provider — a privacy tool silently routing sensitive prompts off the device. Covers `ollamabuildresp` in full, including that its zero token counts and zero cost are **honest** for a local model rather than the hosted-provider defect (asserted so nobody "fixes" them into an estimate that would then be recorded in the audit trail as a measurement), that a real response carries a non-empty `modelid` which is what makes the empty-modelid sentinel unambiguous, and the `usermsg`/`assistantmsg`/`systemmsg` helpers. **Carries a documented finding that is deliberately NOT asserted**: `isavailable(provider)` **SEGFAULTS**. Localised by bisection with progress markers — `ollamabuildresp` returns, `olp.new` returns, `olp.isavailable` faults — and it is *not* `core.models.ollama.healthcheck`, which was probed separately and completes normally including the three-arm match on its result. `$ollamaprovider` declares `client:i64` and `olp.new` stores an `$ollamaclient` struct into that field; `isavailable` passes `provider.client` back to `ollama.healthcheck`, which expects the struct. A struct laundered through an `i64` field and read back faults — the "reading a field off a mis-matched value SEGFAULTS" class. `completeplain` passes `provider.client` to `sendchatplain` in the same shape, so the local dispatch path is on the same footing, and neither is asserted: a segfaulting test reports a signal (139) rather than an assertion count and tells a reader nothing. On a machine with no Ollama running — the normal state for most installations — anything asking whether the local provider is available dies. Depends on `std.test`, `std.str`, `core.providers.types`, `core.providers.ollamaprovider`.
