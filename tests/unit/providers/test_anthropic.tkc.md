Tests `core.providers.anthropic` by importing it (X7.2), together with `core.providers.types`, which must be imported for `$completionresponse`'s field names to resolve. The file it replaces declared its own `extractcontent` "stub: extracts content[0].text from a mock response" — a function the module does not have — so it reimplemented the extraction it imagined and never touched `buildresponse`, which is where the defects are. Covers the client configuration, the `nocompletion`/`iscompletion`/`completionerror` sentinel (a plain struct and a predicate rather than a result, because T-18 makes a user-declared error arm dead and reading a field off the mis-bound value segfaults), that a failure message carries no API key fragment, `parseplain` on a real `/v1/messages` body, and the fail-safe that an unparseable body yields the sentinel rather than an empty success. **Carries five RED assertions for two live defects, both measured, both reported and not fixed.** (1) `buildresponse` reads the nested usage object with `json.str` — which extracts a *string*, not an object — and writes the match arms error-first, and `mt` on a stdlib result binds arms **by position, not by label**; so against a body carrying `"usage":{"input_tokens":150,"output_tokens":42}` the measured result is `content == "Hello there"` and `modelid == "claude-sonnet-4-20250514"` correct but `inputtokens == 0` and `outputtokens == 0`. `browser/pages/api/pipeline.tk` writes those straight into the audit event, and `audit_log` is append-only with a hash chain over exactly those columns, so the zeros are **permanent** and every cost, savings, quota and scorecard figure derived from them is zero while reading as a measurement; `nocompletion()` also yields 0 and 0, so a failed call and a successful one are indistinguishable in the trail. This is the second spelling of the defect — the first, in `pipeline.usagetokens`, was deleted in a dispatcher rewrite and the replacement reproduced it — and these assertions are what stops a third. (2) `calccost` returns a bare `f64` across a module boundary, which T-20 corrupts: expected 0.00108 for Sonnet 150/42, measured 0; expected 0.0048 for Haiku 1000/1000, measured `4.94066e-324` (the smallest denormal, bit pattern 1). The rendered value depends on the call site, so the same call can look different in different binaries. Depends on `std.test`, `std.str`, `core.providers.types`, `core.providers.anthropic`.
