Tests `core.governance.compliance` (X7.2). The file it replaces declared an `overallstatus` taking COUNTS, where the real one takes the checks and inspects their status strings — so the thing that can actually go wrong was unreachable — and had no database, leaving all five live checks entirely untested while being the substance of every compliance report this project emits. Covers the status ladder on real `$compliancecheck` values: FAIL dominates WARN dominates PASS in both arrival orders (a ladder returning the last status it saw would pass one and fail the other), ASSERTED being non-blocking so it does not drag a passing report down, and an empty list being a vacuous PASS rather than a crash. Then the live checks against a fresh store: `checkauditrecording` and `checkaudittrailcomplete` FAILING on an empty `audit_log` — both used to report PASS, meaning a report said the audit log was enabled on an installation that had never recorded a request — then PASSING with two real events, with the detail stating the count; completeness RUNNING the verifier, so its detail is the verifier's own verdict and no longer quotes GA5.3; `checkappendonly` PASSING from the live triggers with a detail that states the control's LIMIT rather than overselling it; `checkencryptionatrest` WARNING rather than claiming PASS on plain SQLite; and a missing consent table being WARN, never PASS. Finally both framework reports: check counts, `overall` being WARN rather than PASS and being derived from their own checks, and `formatreport` rendering every row including the ASSERTED ones. Depends on `std.test`, `std.str`, `std.file`, `std`, `core.storage.db`, `core.storage.audit`, `core.governance.compliance`.
