Tests `core.governance.gateway` by importing it (X7.2). The file it replaces asserted story T4.5's acceptance criterion — "gateway blocks RESTRICTED request when kill switch engaged" — against an `if` statement written three lines above it in the test. Importing the real module produced two findings, and the first is why this file deliberately does NOT call `gw.submit`.

**FINDING 1: `gateway.submit` SEGFAULTS on a valid request.** Reproduced, minimised and localised: `gw.submitinner(gw.new();req)` with `req.usecaseid="chat-completion"` — a built-in use case — dies with SIGSEGV, while every component it calls works standalone (`uc.newregistry`, `uc.find`, `found.risklevel`, `pol.classifyrisk` with a real `$risktier`, `gw.submitinnerunknownuc`, `gw.new`). The mechanism is a type mismatch the compiler cannot see, at `gateway.tk:92-94`: `submitinnerwithuc`'s third parameter is declared **i64**, so `founduc.risklevel` is not type-checked against anything, and `$usecasedef.risklevel` is a plain **i64** (0/1/2) — but `pol.classifyrisk` declares that parameter as **$risktier**, a sum. A raw small integer reaches a `mt` that dereferences it. `submitinner`'s own `mt uc.find(...)` compounds it: T-18 takes the FIRST arm whatever the value is, so `submitinnerunknownuc` is unreachable dead code and an unknown use case binds the error payload as the use case.

**FINDING 2: the gateway's kill switch cannot be engaged.** `gateway.tk:148-158` — `activatekillswitch` is two `==` comparisons whose results are discarded (T-26 followed to its conclusion: `gw.killswitchactive=true` raises E2002 whose advice is "use ==", and that advice is a silent no-op). It could not work with `=` either, since `gw` is a value parameter and a `:void` signature has no way to return a new struct. `new()` sets the flag false, nothing can set it true, so `submit`'s deny branch is unreachable in the product. `deactivatekillswitch` is the same.

**Scope:** the module IS imported by `packages/cli/src/ask.tk:12` and `packages/browser/extensions/core.tk:11`, but neither calls `submit` — ask.tk:186 calls only `defaultrouting()` and extensions/core.tk:41 only `new()`. The governance gateway is imported, constructed, and never used to gate a request; nothing crashes today because nothing calls the crashing function, and nothing is governed by it either. loke's working kill switch is `core.governance.killswitch` (see `test_kill_switch.tk`), which is not connected to this gateway.

Covers what can be exercised without crashing: construction; `isblocked` on all four decision variants, since getting it wrong in the permissive direction sends data that should have been held; `submitinnerunknownuc`'s fail-closed DENY at HIGH risk, naming the unrecognised id and recording that the refusal is audited; `defaultrouting` being an explicit placeholder rather than a fabricated figure; and both setters proven inert. T4.5 is recorded as a REOPEN in `docs/epics-and-stories.md` rather than as a crashing test — a segfaulting test reports as CRASH, takes the runner's exit status with it, and buries the finding. Depends on `std.test`, `std.str`, `shared.types`, `core.governance.types`, `core.governance.gateway`.
