Tests `core.governance.quota` against the real `quota_rules` and `quota_usage` tables (T4.2). The file this backlog row names has never run: it exists only under `_archived-tests/`, which `scripts/run_tests.sh` excludes from discovery, and it is written against a pre-toke API (`db.newmemorystore`, `str.arraypush`). Five of the row's six behaviours have direct equivalents and are asserted by equality rather than by sign: not exceeded below the limit (250 of 1000 is 75% remaining), EXCEEDED at exactly the limit (`exceeded` is `!(remaining > 0)`, so the boundary is inclusive and the thousandth token is the last one allowed), exceeded above it (reported as a negative percentage, not clamped), `remaining` as `remainingpct` with the used counters asserted alongside it, and an unknown scope answering 100% with an empty rule id. The sixth, `reset`, has no equivalent — nothing in the module clears or decrements a counter — so what is asserted instead is the design's actual reset: PERIOD ROLLOVER, by moving a spent daily rule's usage row into a past `period_key` and showing the counter start again from zero while the old row is retained. The same technique, and the same reason, as the elapsed auto-release in `test_kill_switch.tk`: `periodkey()` reads the clock and takes no argument, so the elapsed case is unreachable through the module's own API. Also covers usage ACCUMULATING rather than overwriting (the `ON CONFLICT DO UPDATE`), one usage row per (rule, period) rather than one per call, scope isolation, the money path through `rowf64hundredths` to the cent, `setrule` as an upsert that does not leave a second rule for a scope `findrule` reads with `LIMIT 1`, and the four period keys. Two measurements are recorded in the header as comments rather than assertions, both reported for decision rather than fixed: `check()` DISCARDS its `tokens` and `cost` arguments, so asking whether 5000 tokens fit a 1000-token quota answers "fine"; and a scope with no rule, or a rule whose limits are both zero, is UNLIMITED — a spend control that fails OPEN, the opposite of how the kill switch treats an unreadable flag. Nothing in the product calls this module yet. Depends on `std.test`, `std.str`, `std.file`, `std`, `std.db`, `core.storage.db`, `core.governance.quota`.
