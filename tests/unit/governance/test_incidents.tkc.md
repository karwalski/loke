Tests `core.governance.incidents` against the real `incidents` table (X7.2). The file it replaces declared its own incident array and its own severity constants — `f=sevp0():str{ <"P0" }` compared to the literal `"P0"` — and never labelled itself a stub. The real constants are what the table stores and `statusresolved()` is half of `listopen`'s WHERE clause, so a silent rename would leave resolved incidents on the open list forever. Covers: the severity ladder and status vocabulary from the module; table creation read back from `sqlite_master` rather than inferred; `openincident` returning a 32-character id, writing exactly one row, and setting status `open` itself rather than trusting the caller; the full lifecycle with the assertion that makes `listopen`'s predicate meaningful — an incident under INVESTIGATION is still open, and only `resolve` takes it off the list while retaining the row, because an incident log that deletes on resolve has no history; the resolution note, which is the only record of why something was closed; and `autoopenifdegraded` on both sides of its `< 0.5` threshold, checking the row count after each so that "returns false" and "opened nothing" are separate claims. Also asserts the auto-opened incident is P2 and names the model in its title, and that `formatincidents` carries severity and title into the operator's view. Depends on `std.test`, `std.str`, `std.file`, `std`, `std.db`, `core.storage.db`, `core.governance.incidents`.
