Tests `core.governance.alert` by importing it (X7.2). The file it replaces declared its own `shouldquotaalert(remaining;threshold){ <remaining<threshold }` and asserted that 10 is less than 20. Covers the parts of the real rule the stub had no notion of: the default configuration being log-only with an empty webhook URL, so nothing leaves the device unconfigured; `makealert` carrying kind, severity and message, with a 32-character id and a real timestamp, and two alerts made with identical arguments getting different ids; `alerttojson` field by field, since that string is what a webhook receives; `send` succeeding both in log-only mode and with delivery enabled but no URL, which is a no-op rather than a failure; `quotaalert`'s two halves — the threshold, asserted on both sides of the boundary because the test is `<` not `<=`, and the `exceeded` flag forcing an alert even when `remainingpct` claims there is plenty left; and `policyalert`'s message carrying rule, regulation and action, all three of which an operator needs to act on. **Not covered, stated rather than stubbed:** the webhook delivery path, because `send` posts through `std.http` and there is no loopback listener in this suite. Depends on `std.test`, `std.str`, `core.governance.alert`.
