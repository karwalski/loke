The file it replaces asserted its own division — that 0.75 > 0.7 — where the real module computes that rate from rows inside a time window, and it is the WINDOW, not the division, that is broken. **FINDING, latent: the trend window matches EVERY row, always.** `monitoring.tk:63` writes `created_at` as a SQL LITERAL — `VALUES (...,'now()')` — so every row's `created_at` is the seven characters `n-o-w-(-)`. `computetrend` then filters with `created_at >= datetime('now','-N days')`, comparing `"now()"` against `"2026-08-24 07:00:00"`; `'n'` sorts after `'2'`, so the predicate is TRUE for every row forever. A 1-day trend and a 3650-day trend are the same number, and a model whose quality collapsed a year ago still drags down today's figure. This is the GA5.1 defect (the literal `'now()'`) and the GA5.11 defect (a window comparing incomparable text) in the same two lines; both were fixed in `audit_log` and both are still live here.
