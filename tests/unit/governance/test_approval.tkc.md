Tests `core.governance.approval` by importing it (X7.2). The file it replaces declared a two-parameter `requiresapproval`; the real one takes five, and the fifth — the list of "don't ask again" rules, the only way this control can be turned OFF — was exercised by nothing. Covers all four modes in both directions, the local-provider exemptions (ollama, mlx) against the hosted providers, and the fact that a MISSPELLED mode silently requires no approval because the fall-through is not fail-closed. **Two production defects characterised, both latent** — `requiresapproval` and `generatediff` have no caller anywhere in `packages/` or `src/`, checked by grep, so the approval gate is a module nothing invokes: (1) `approval.tk:45-50` matches suppression rules on `tasktype` ALONE, so `$dontaskrule`'s `providerid` and `maxsensitivity` are declared and never read — a rule created for a chat to ollama at internal sensitivity also suppresses approval for a RESTRICTED chat to anthropic, escaping both scopes it declares, and it overrides mode `always`; (2) `approval.tk:81`'s loop condition `!(i>maxlen)` runs maxlen+1 times, appending a blank "unchanged" line to every diff, so a two-line prompt yields three diff lines — the `find_offbyone_loops` class, visible as a blank row at the bottom of every approval dialog. The assertions naming these are worded "DEFECT CHARACTERISED" so a reader cannot mistake them for the intended contract; if the functions are ever wired up they become the failing tests that describe the holes. Depends on `std.test`, `std.str`, `core.governance.approval`.
