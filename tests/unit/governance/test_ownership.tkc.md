Tests `core.governance.usecases` (X7.2) — **re-targeted, and the re-targeting is the finding.** The file it replaces declared a three-role `$ownershipstore` (business, technical, risk owner); `docs/test-coverage.md` maps it to `core/governance/policy.tk (ownership)`. Both are wrong and neither is reachable: `core.governance.policy` has no ownership concept at all (it exports only `escalate`, `classifyrisk`, `evaluatelow`, `evaluatehigh`, `evaluate`, `extracontrols`, `controlsforrisk`), and the module the stub actually mirrors is `governance.ownership` in the legacy foundation tree at `src/governance/ownership.tk` — field for field — which is NOT built into anything the test runner can reach: there is no `governance.ownership` interface in `build/interfaces` (that holds the `packages/` tree) and `run_tests.sh` links `packages/browser/build/ooke`, which contains no legacy-tree objects. Importing it fails at E2030. So the three-role store is **untestable from this suite** until the legacy `src/` tree is built and linked — a runner and build-graph question, not a test-authoring one.

What is live and ships is ownership on the use-case registry, and `core.governance.usecases` had no test file of any kind, so this is strictly more coverage than a stub of an unreachable module. The registry is also what `core.governance.gateway` consults on every request. Covers: the eight built-ins; **every** use case declaring an owner, asserted over the whole list so a ninth added without one fails here, because an unowned use case is one nobody is accountable for; every one stating its purpose, which is what purpose limitation is assessed against; each id declared exactly once, since the gateway looks a request up by that exact string and a rename silently turns every request of that kind into an unknown use case; the three risk levels by name, so an autonomous agent task cannot be declared as low-risk as a summary; and `register` — whose body was `registry.entries==@(registry.entries;uc)`, a discarded comparison wrapped around a nesting literal against a struct a callee cannot mutate, in a function declared `:i64`, four independent reasons it registered nothing and reported success (LS1.1a) — now growing the registry, making the entry findable with its owner, and leaving the registry passed IN unchanged, which is the property the old signature could not express. **Not tested, and why:** `uc.find` on a missing id, because T-18 binds the error payload as a `$usecasedef` and reading any field off it segfaults — the same consequence that makes `gateway.submitinnerunknownuc` dead code.
