Tests `core.storage.db.resolvedbkey`/`ensuredbkey` against a real keychain (X8.3): a throwaway keychain file created under the test's own throwaway HOME with `std.keychain.create` and selected with `std.keychain.use`, never the user's login keychain (X8.7). Asserts `dbkeyaction` over every kind `std.keychain.lasterrkind` reports — only `notfound` may generate; `locked`, `denied`, `nokeychain`, `failed`, `unavailable`, an unknown kind and a malformed value are refused. Then, end to end: an absent item is generated, stored and used on the next call; a LOCKED keychain holding the key is refused with kind `locked`, and after unlocking still holds the original key; on a LOCKED EMPTY keychain the lookup still answers truthfully (measured: `notfound`, not `locked`), so the first-use branch is taken, the store fails `locked`, no key is returned, and after unlocking the keychain holds no key. The locked-with-key case asserts the decision (`action` 0), not only the empty key, because "generated but could not store" also returns an empty key. Locking and unlocking use `/usr/bin/security` on the throwaway file's absolute path only; an empty path is refused, because `security lock-keychain` with no path locks the user's default keychain. Depends on `std.test`, `std.str`, `std`, `std.process`, `std.keychain`, `core.storage.keychain`, `core.storage.db`.
