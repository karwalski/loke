Tests the JOIN between `core.storage.keychain` and `browser.pages.api.settings` (X7.2). The file it replaces was two module-level `mut` strings plus a `stubsetapikey`/`stubgetapikey` pair, and its nine assertions all read back a value assigned a line earlier — "anthropic key roundtrip" asserted that assignment works. It named neither real module. Each side of the boundary now has its own test (`tests/unit/storage/test_keychain.tk`, `tests/unit/browser/test_settings_handler.tk`) and neither crosses it; this one does, through `keyfordisplay`, which reads the keychain and decides what a user is shown. Covers: a stored provider key reaching the endpoint masked, with the secret absent from the response, and with nothing in the test reconstructing the `api_key.` account name — so a disagreement between `setapikey` and `keyfordisplay` about the prefix fails here; a provider with NO stored key reported as "not set" rather than as a masked non-key, which is the branch that depends on `getkey` returning a NULL whose `str.len` is 0 while `str.eq(…;"")` is false; the `maskordefault` boundary asserted on both sides (four characters is too short to mask without showing the value in full); and the rendered `settingsjson()` body carrying neither a whole key nor the text `(null)`. Every account is unique to this test and deleted at the end, because a keychain read by a differently-named binary can block on an authorisation dialog a headless process cannot answer. Depends on `std.test`, `std.str`, `core.storage.keychain`, `browser.pages.api.settings`.
