# Claims Register

**Version:** 1.0
**Last updated:** 2026-09-19
**Story:** X6.1

Every externally-visible claim loke makes, mapped to the code that implements it and the test or
measurement that proves it. A claim that cannot be traced to both is not a claim loke is entitled to
make, and this file says so.

## Precedence and scope

[metrics-baseline.md](metrics-baseline.md) is the only source from which this project publishes
figures, and it takes precedence over this file and over every other page. **This register therefore
does not restate any figure.** Where a claim *is* a figure, the row names the claim and points at
metrics-baseline rather than repeating the number. If this file and metrics-baseline ever disagree
about a figure, metrics-baseline is right and this file is a bug.

Scope is the externally-visible surface: `README.md`, `docs/features-loke.md`,
`docs/features-moke.md`, `docs/architecture.md`, and the public site at loke.tokelang.dev. Internal
specification documents are out of scope unless a claim from one has escaped into the four files above.

## Verdicts

| Verdict | Meaning |
|---|---|
| `verified` | The code does what the claim says, and a named file and line prove it. It does **not** mean a figure has been measured or that a test exercises the path — the *Proof* column says which. |
| `partial` | The mechanism exists but the claim overstates it: narrower scope, an unwired path, a known defect, or a figure with no measurement. |
| `stub` | Code exists with the right shape and the wrong behaviour — a fixed return value, an ignored argument, a hardcoded result. Reads as implemented; is not. |
| `absent` | No implementing code was found. |

A row's *Proof* column names a committed test or measurement, or the story ID that would create one.
"No test" means no committed test exercises the production module. Because 54 of 86 test files
re-declare their subject rather than importing it (see [test-coverage.md](test-coverage.md)), a test
file merely *existing* for a module is not proof and is not recorded as such.

over 2423 assertions, and no pass has been made over this register to re-attribute the rows that gained
a real test. Doing so is the remaining half of RV1. Until it is done, read this paragraph as a floor,

Two patterns account for most of the non-`verified` rows. The first is **written but unwired**: a
module compiles, is documented as a feature, and has zero importers — all of section B, plus D6, J1
and K3. The second is **shape without behaviour**: a function with the right signature returning a
fixed value — E5-E9, F1, F2, G2, K2-K4.

Three findings dominate the rest.

**The browser's live request path did not use the privacy pipeline (A13). Fixed 2026-09-22.** The
route registered for `/api/pipeline` called the sidecar over HTTP and, when the sidecar did not answer,
fell through to five literal column-name checks that incremented a counter without altering the text —
then posted that unaltered text to the provider while reporting an entity count and a sensitivity
label. It now routes through `core.privacy.pipeline.runforward`, forwards only `res.anonymised`,
refuses with 503 when no detection layer completed, and treats an unreadable kill switch as engaged.
Asserted in `tests/unit/privacy/test_fail_closed.tk` rather than argued (NC1.9, commit `027e383`).

**What is still absent on that path**, updated 2026-09-23. Of the nine capabilities claimed at
`docs/features-loke.md:52`, the path now has detection, anonymisation, the kill switch, the fail-closed
refusal, **response restoration** (GA1.2), **audit logging** (GA1.4), **policy evaluation** (GA1.8),
the **semantic cache** (GA1.6) and **intelligent routing** (GA1.7, four selectable strategies). The one
that remains absent is **token optimisation** (GA1.5): nothing in `pipeline.tk` calls `toon.encode` or
`llmlingua.compress`, and wiring it today would wire a fail-open, because `llmlingua.isavailable`
returned TRUE for an absent sidecar until the T-31 sweep and `toon`'s savings measure is a character
ratio (C1). A tenth thing is claimed nowhere and worth stating: the **pre-flight cost estimate** is
still `0.0` on every request (C4, GA1.5a), so governance decisions are taken as though requests were
free.

**The audit trail is now written (E4).** This paragraph said "never written" and that is no longer
true. `core.storage.audit.insertevent` is called from the browser route — at the route, not the
dispatcher, because `core.providers.dispatcher` is imported by three modules and none is route
reachable, so auditing there would have logged zero events for real traffic. A failed provider call is
audited too. Asserted by a **row-count delta of exactly one** in
`tests/integration/test_audit_trail_e2e.tk`, plus tamper detection, gap detection and rejection of an
`UPDATE` on the table. The digest is a real hash chain over the previous hash plus all fourteen fields
(GA5.1, GA5.2), and `logevent` was separately unable to write a row at all until a reversed `str.join`
was fixed (T-23).

**Two columns in that trail were zero for every hosted request until 2026-09-23**, and this is the kind
of thing the register exists to say out loud: `tokens_in`, `tokens_out` and `cost_usd` were all `0`,
because both providers read the nested `usage` object with an accessor that refuses objects (T-32) and
computed cost through a bare `f64` return that a module boundary corrupts (T-20). The table is
append-only and hash-chained over exactly those columns, so **rows written before that fix carry
permanent zeros and the chain attests to them**. Any figure derived from audit history predating
2026-09-23 is therefore wrong in those three columns and cannot be corrected in place. See
[E. Governance, audit and compliance](#e-governance-audit-and-compliance).

## Maintaining this register

1. A new externally-visible claim arrives with its row, or it does not ship.
2. A row moves to `verified` only when the *Implementing code* column names a file and a line, and the
   *Proof* column names a committed test or a metrics-baseline entry. `scripts/check_claims.py`
   enforces the first half of that in CI (X6.3).
3. When a story listed in a *Proof* column lands, the row is re-verdicted in the same change.
4. Figures live in [metrics-baseline.md](metrics-baseline.md). This file points at them and never
   restates them.
