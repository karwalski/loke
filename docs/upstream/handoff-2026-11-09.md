## 3. New issues

### T-60 — `==` on arrays compares addresses, or bytes as a C string

**Severity: correctness, silent. It hid every failed `process.spawn` in loke** (F10.44).

**Measured** (`repro-2026-11-09/T-60/`, three programs):

- `let a:@str=@(); a==@()` is **false** although `a.len` is 0. The IR is `icmp eq i8*`
  against a fresh `malloc` block, so a comparison with the literal can never be true.
  `let x=@(); let y=@(); x==y` is **true** (it lowers to `tk_str_cmp`), and `x==@()` is false
  again. Exit 2; expected 7.
- **New since loke filed T-60:** between two named typed arrays, `==` lowers to `tk_str_cmp`
  on the array blocks, so it compares the element bytes as a C string and stops at the first
  zero byte. `@(1;2)==@(1;2;3)` is **true**, `@(256)==@(512)` is **true**, `@(1;2)==@(7;8)` is
  false. Exit 3; expected 0.
- The idiom it broke: after `mt process.spawn(@("/nonexistent/…")) { $ok:h h; $err:e @() }`,
  the spawn failed (`failed=true`) and `h==@()` is **false**, so a caller goes on to
  `process.stdout(h)` and `process.wait(h)` with the empty array's address as the handle. In
  loke's first draft of MK19.9 that blocked in `wait4` for good. (The reproducer stops before
  any wait.)

**EXPECTED:** `==` on arrays compares elements, or is refused at compile time.

**Workaround in loke:** every spawn's error arm is `0` and is tested with `h==0`. The runtime's
own bad handle is NULL, so on it `process.stdout` takes `$err`, `process.wait` answers -1 and
`process.kill` false: a missed check fails closed. `scripts/find_empty_array_sentinel.py`
(in the quality gate) fails on any `== @()` or `!= @()` and on any spawn match whose error arm
is not `0`; on the tree before the fix it found 202 sites.

**Ask:** make `==` on arrays element-wise, or reject it with a diagnostic pointing at `.len`;
and give `process.spawn` a failure value that cannot be mistaken for a handle, or have
`process.wait` refuse an address it did not hand out.

### T-62 (loke F10.42) — an `@@str` row subscripted inline as a call argument emits invalid IR

**Severity: build break. Not silent, but `--check` passes and the error is in LLVM's words.**

**Measured** (`repro-2026-11-09/F10.42/`):

```
let rows:@@str=@(@("a";"b");@("x";"y"));
if(str.eq(rows.get(i).get(0);"x")){ … }
```

`--check` rc 0; the build fails at clang with
`error: '%t65' defined with type 'ptr' but expected 'i64'` (`call i64 @tk_str_eq_w(i64 %t65,
…)`), reported as E9003 "while compiling f=main". The element is loaded as `i8*` and passed
where the callee takes `i64`. **It is not specific to std:** a user function
`f=eq3(a:str):bool` given `rows.get(0).get(0)` fails the same way (`inttoptr i64 %t61`).
`bound.tk`, the same program with `let row:@str=rows.get(i);` first, compiles and prints `n=1`.

**EXPECTED:** compiles and runs; exit 1.

**Workaround in loke:** bind the row with its declared type before subscripting it
(`tests/unit/nocustody/test_artifact.tk`, `packages/moke/tests/test_upload_csv.tk`).

**Ask:** load the inner element with the outer array's element type, or have the checker refuse
the shape until it does.

### T-64 — a per-read timeout ends a response as `$ok` with a short body

**Severity: silent wrong result. Found while measuring T-63 for this handoff.**

**Measured** (`repro-2026-11-09/MK19.11/`, the `stall` case, plain http on loopback): a server
answers `Content-Length: 8`, sends three body bytes and then nothing for 45 s.
`http.geturl` returns **`$ok` with a 3-byte body** after 30,001 ms — the per-read timer fired
and was read as the end of the body.

**EXPECTED:** `$err` (a transport failure) when the body is shorter than its `Content-Length`,
or when the connection ends before a chunked body's last chunk.

**Workaround in loke:** none in the client. loke's one fetch of untrusted servers (moke's
`/api/proxy`) uses the system curl (T-63). loke's other callers are local services whose
answers it parses as JSON, so a cut answer would most likely fail to parse; that is not
measured.

**Ask:** treat a short body as a transport error, in `http.geturl`, `http.clientget` and the
client used by `http.postheaders` (only `http.geturl` is measured here).

### T-63 (loke MK19.11) — an https client that can be told where to connect, with a body cap and a deadline

**Severity: feature ask with a security reason. Not a defect in what the client claims to do.**

moke's `/api/proxy` fetches a URL a user supplies (MK19.9). It is an SSRF surface by
construction, so it must refuse private, loopback, link-local and metadata addresses. The
threats the toke client cannot answer:

- **DNS rebinding.** The client resolves the host itself, inside connect, and takes no address
  (read from `src/stdlib/http.c` `client_do_request` at 3.1.0); std exports no general
  resolver (the only `resolve` in the `.tki` files is `mdns.resolve`). So a program can check
  one resolution and the client connects to a second, which an attacker's DNS server can point
  at 127.0.0.1 or 169.254.169.254.
- **Slow drip.** Measured (`MK19.11`, `drip` case): a server sending `Content-Length: 8` and
  one byte every 5 s held `http.geturl` for **40,041 ms** and the call answered `$ok`. The only
  clock is the 30 s `SO_RCVTIMEO`, which restarts on every byte, so one byte every 29 s holds
  a caller indefinitely. (The 40 s case shows the restart; the indefinite case is inferred,
  not run.)
- **No body cap.** Measured (`big` case): a 64 MiB body was read whole into memory and answered
  `$ok`, length 67,108,864.

**What loke does meanwhile:** `moke.proxy.fetch` runs the system curl by absolute path, without
a shell, with `--resolve` (connect to the address loke checked, verify the certificate
against the name), `--max-filesize`, `--max-time`, `--proto =https`, `--max-redirs 0` and
`--noproxy '*'`. `packages/moke/tests/test_proxy_fetch.tk` covers it.

**Ask, in order:** (1) a client option to connect to a given address while verifying the
certificate against the URL's host name (curl's `--resolve`); (2) a resolver that returns
every address for a name; (3) a body-size limit enforced while reading; (4) a deadline for the
whole request. With those, loke moves the proxy off curl and keeps its test.

### O-4 (ooke) — the template engine renders an unknown directive, and an unclosed block, as nothing

**Severity: silent loss of a page's content.** Filed in `ooke-issues.md` on 2026-10-07 (loke
F10.8); still holds at rc.2.

**Measured** (`repro-2026-11-09/O-4/`, rc.2's own `src/template.tk` through
`tplrenderfile`, with a layout `<title>{! yield("title") !}</title><main>{! yield("body") !}</main>`):

| template | rendered | answer |
|---|---|---|
| `control.tkt`, blocks closed with `end` | `<title>T1</title><main>BODY</main>` | `$ok` |
| `unknown.tkt`, `A{! frobnicate("x") !}B` | `AB` | `$ok` |
| `endblock.tkt`, body block closed with `endblock` | `<title>T1</title><main></main>` | `$ok` |
| `unclosed.tkt`, body block never closed | `<title>T1</title><main></main>` | `$ok` |

**EXPECTED:** the last three answer `$tplerr`.

**What it cost loke:** two pages served 200 with the base layout alone and every status probe
passed. **Workaround:** loke's templates use `end`, and `scripts/check_ooke_surface.py` reads
the directive and filter names from the pinned `template.tk` and fails a template that uses
any other or whose `block`/`end` counts differ.

**Ask:** return a `$tplerr` (and log it, per 134.24) for an unknown directive and for a block
still open at the end of the template.

### O-5 (ooke) — the 3.0.0 changelog names a raw syntax the engine does not have

**Severity: documentation; it misleads anyone migrating from 2.0.0.**

**Measured** (`repro-2026-11-09/O-5/`): rc.2's `CHANGELOG.md` says "Use `{{raw ...}}`". With
`x = "<b>"`, the template `A{{raw x}}B|{= x | raw =}|{= x =}` renders
`A{{raw x}}B|<b>|&lt;b&gt;`: the `{{raw}}` form is literal text, the `raw` filter works, and
the default escapes.

**Ask:** change the entry to `{= key | raw =}`.

### T-61 — u32 field plus an untyped integer local → invalid IR: **not reproduced**

Filed 2026-10-01 from `core.privacy.systemprompt`, where `unplaced:r.unplaced+stray` failed at
the LLVM step with `'%t212' defined with type 'i64' but expected 'i32'`. It was seen by one
worker and never reduced, and the failing source was never committed.

On 2026-11-09 at the pin it did **not** reproduce: `repro-2026-11-09/T-61/` (the sum as a
`let`, in a struct literal, in a returned struct declared in another module, with the local
counted in a loop or returned by a function) compiles and exits 5 as expected; and the filed
site, with loke's workaround reverted and compiled against a full loke build's interfaces,
gives IR clang accepts (the add is i64 throughout). See `T-61/result.md`. **loke makes no ask**
and keeps the harmless workaround; it will report again with the source if it recurs.

## 4. Measured since the reply, already in `toke-issues.md`

- **T-48 addendum.** The three-argument client-first call,
  `http.postheaders(http.client(url);body;@(@(name;value)))`, still type-checks (re-checked
  today: `--check` rc 0; the `httpclient` is accepted where the `.tki` declares `str`). Measured
  2026-10-08 against a TLS stand-in: it sends nothing (no handshake reaches the server) and
  answers `$err`. No loke source uses it. **Ask:** reject an `httpclient` where a `str` URL is
  declared, as the four-argument form already is.
- **T-58 addendum.** There is no GET that carries a header: `http.geturl(str)` and
  `http.clientget(httpclient;str)` take none (read from the 3.1.0 `.tki`), and send only `Host`
  and `Connection` (measured 2026-10-08). GitHub's API requires a `User-Agent`, so loke's update
  checks cannot be written (VM1.6g). The Host header also omits the port. **Ask:** a GET with
  headers, typed like `http.postheaders`.

## 8. Reproducing

Every issue in §3 has a directory under [`repro-2026-11-09/`](repro-2026-11-09/); each `.tk`
file's header comment states EXPECTED and the defect.

```sh
cd docs/upstream/repro-2026-11-09
TOKE_DIR=/path/to/toke OOKE_DIR=/path/to/ooke ./run.sh        # everything
TOKE_DIR=/path/to/toke ./run.sh T-60 F10.42                     # a subset; O-4 and O-5 need OOKE_DIR
```

- `TOKE_DIR` is a toke checkout with the built `toke` binary. `OOKE_DIR` is an ooke checkout;
  O-4 and O-5 copy its `src/template.tk` and build it beside the reproducer.
- Each line is `ID | verdict | observed`: DEFECT (the defect as described), OK (the expected
  behaviour), or note. Build products go to `$TMPDIR/loke-repro-2026-11-09/<toke commit>`.
- MK19.11 starts `server.py` on 127.0.0.1 ports 47971–47973, stops it by PID, and takes about
  75 seconds. Nothing leaves the machine. T-60's spawn case spawns a path that does not exist
  and waits on nothing.
