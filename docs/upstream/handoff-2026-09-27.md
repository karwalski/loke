## 1. How to reproduce everything

Every issue has a directory under [`repro-2026-09-27/`](repro-2026-09-27/) holding `repro.tk`
(a header comment states EXPECTED vs the defect), any variants, and `result.md` with the
observed outcome on both compilers.

```sh
cd docs/upstream/repro-2026-09-27
TOKE_DIR=/path/to/toke ./run.sh              # T-1 … T-30 and O-1   (./run.sh T-13 T-20 for a subset)
./run2.sh /path/to/toke                      # T-31 … T-57 and the R1-R8 capability probes
```

Each prints one line per issue: `ID | verdict | observed outcome`. The runs behind this document
are saved as `results-pin-0b0bc4e.txt`, `results-head-4a50b87.txt`, `run2_pin.txt` and
`run2_head.txt`.

- Programs that touch the network, files or processes need `--allow-net` / `--allow-read` /
  `--allow-write` / `--allow-run` (or `--allow-all`) at run time; the runners pass them.
- Local servers bind `127.0.0.1` ports 11441–11446 and 47913 only, and are stopped by PID.
  Nothing is sent off the machine. No paid provider and no real keychain is touched.
- **If your checkout lives at a long path, `std.http` programs fail to link** (N-1 below).
  `w2tools/tkbuild.sh` works around it; `run2.sh` uses it.

## 3. What blocks loke — in priority order

These are the items with **no workaround in loke**, or whose workaround leaves a user exposed. **B0 is the most urgent: it is a security defect in toke itself.**

| # | Ask | Why it matters to loke | Evidence |
|---|---|---|---|
| **B0** | **Verify the server certificate in the https client** (T-58, found after this document was first written). `tk_http_postheaders_w` creates a `TLS_client_method()` context, sets SNI and connects, and never calls `SSL_CTX_set_verify`, `SSL_set1_host` or `SSL_get_verify_result`; OpenSSL's client default verifies nothing. | **Security.** Every hosted provider call carries an API key. A local probe presenting a self-signed certificate for `CN=probe.invalid` received the request, `authorization` header included. loke now refuses every non-loopback send until this is fixed, so no hosted provider works through loke. | Read at `tk_web_glue.c:1853-2055` on the pin (and `:1749` on main, same code); probe in `toke-issues.md` T-58. **Ask:** verify peer and hostname by default, fail the call on a bad certificate, and expose the failure so a caller can tell it from a network error. |
| **B1** | **Choose the address a server binds** (R1, T-43). `http.serve`, `serveworkers`, `servetls`, `servetlsworkers` and `http.listen` take a port only; the glue passes a `NULL` host. | loke is a local-first privacy proxy. Its API listens on **every interface**, so any device on the user's network can reach it. Story GA2.5 is blocked on this. | `lsof` shows `*:11441` and `*:11442`, including for `http.listen("127.0.0.1:11442";…)`. Both compilers. `T-43/` |
| **B2** | **`mt` must bind a result's arms by label, and must discriminate a user-declared error type** (T-18, T-31). | Every error path in loke. A failed scan read as success is how a Presidio that was never reached was counted as a completed privacy layer. loke now avoids `!$userErr` results entirely (sentinel structs + predicates), which works but is a convention, not a guarantee. | T-18: exit 57 (always the first arm). T-31: a valid input with the err arm written first takes `err`. Both compilers. |
| **B3** | **`http.get(client;path)` and `http.delete(client;path)` register a route instead of sending a request, silently** (T-57, T-15, R7). The return reads `$ok` from the 257th call, when the route table is full. | This made loke's privacy detection layers report down for months, and could flip them to "healthy" with nothing sent. loke now uses the one-argument form; there is **no client DELETE reachable from source** (`tk_http_delete_w` exists in C). | Recorder sees zero `/health` requests; first `$ok` at call 257, 44 of 300. Both compilers. `T-57/`, `T-15/` |
| **B4** | **Keychain: distinguish "no item" from "query failed"** (R4), and **provide a throwaway keychain** (R5). | loke's database key lives in the keychain. A locked or denied keychain reads as "no key", so the first-use branch runs (X8.3). loke's keychain tests write to the user's **login keychain** (X8.7). | `keychain.get -> ?(str)`, `exists/delete -> bool`; `keychain.c` returns NULL/0 for any non-success `OSStatus`. No API names a keychain. Identical on both. |
| **B5** | **An f64 returned across a module boundary must survive** (T-20). | Every figure loke computes in one module and reports from another. loke formats to a string inside the computing module as a workaround. | exit 5 (expected 55); `declare fastcc i64 @lib_f64abs(double)`. Both. |
| **B6** | **`std.db`: more than one connection** (R8, T-30), and **`db.exec` must run every statement it is given or refuse** (T-40). | A second `db.open` silently repoints every later query, including the audit trail's. A multi-statement migration applies its first statement and reports success. | Two opens both return handle 1. T-40: only table `x` exists after exec reports ok. Both. |
| **B7** | **ooke: build on current toke** (O-1). | loke cannot move its toke pin forward past `060e11b` until ooke does. | §4. |
| **B9** | **Scope capability grants to paths, hosts and programs, and stop a launcher adding grants with `--allow-*`** (T-59, found 2026-09-28). | loke grants only fs_read, fs_write, net and process_spawn, measured as the minimum each binary needs, but a quoted path or host in `[capabilities]` silently grants the whole class, listening and connecting are one `net` grant, and anyone launching the binary can add any class. `env = true` means env_write, and `enforce = false` does not disable enforcement, contrary to the docs. | `toke-issues.md` T-59; `scripts/check_capabilities.sh` and `scripts/lib/cap_probe.tk` measure it. |
| **B8** | **HTTPS POST with custom headers, measured** (R6, T-48). | loke's Anthropic/OpenAI dispatch. `http.postheaders` is `( i64, i64, i64, i64 ) -> i64 [abi]` and the glue reads `(url, body, headersjson, ignored)`. Measured locally since (no provider involved): URL-first **does** arrive over https — and does so without verifying the certificate, which is B0. ## 9. What loke is doing on its side

- Staying pinned at `0b0bc4e` until O-1 is fixed, then fixing the 37 diagnostics in §5.
- Using `--max-imports` for moke's handler registry (story MK6.5) now that it is measured to work.
- Calling `http.postheaders` URL-first where it must call it at all, pending B8.
- Avoiding `!$userErr` results across modules (sentinel structs + predicates), formatting f64
  to str before it crosses a module, one-argument `http.get` only, and `$ok` first in every match.
  These conventions are enforced by checks in `scripts/quality-gate.sh`; they are workarounds,
  and each would be retired by the corresponding fix above.
