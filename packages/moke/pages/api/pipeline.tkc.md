Pipeline API endpoint that applies schema-first hooks, forwards prompts to the loke pipeline upstream at port 11430, and appends console log metadata to the response. GET answers a readiness probe; POST does the work. The upstream call goes through http.post(url;body) — two arguments, not three — and an empty response body is the failure signal, because std.http exposes no way to read a status code and http.ok has no runtime symbol. Depends on std.http, std.json, std.str, std.time, shared.jsonobj, moke.hooks, and moke.consolelog; the moke.compute import was unused and is gone.

BG1.4: POST first refuses a foreign Origin or a non-loopback Host (shared.origin.requestrefused, the GA2.6/GA2.7 rule loke applies), because this route reaches loke with no Origin and would otherwise let a foreign page drive loke through moke. A body in loke's own shape (`islokeshaped`: it has `text` and no `prompt`) is a page that sent loke's request to moke's origin because window.LOKE_URL was ''; it is relayed unchanged to loke's /api/pipeline through moke.lokerelay.postto, and loke's status and body are answered as they came. loke runs the privacy pipeline on it. A `prompt` body takes the schema-first path above, as before.
