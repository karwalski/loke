CLI ask command handler. Parses ask-specific options (--model, --dry-run, --stream, --system, --tolerance), runs the user prompt through the privacy pipeline for PII anonymisation, routes it to an appropriate LLM via the router and dispatcher, and prints the response with pipeline stage indicators and audit logging. Exports the $askopts type and the parseopts, defaultopts, run, and usage functions. Depends on shared.types, shared.log, shared.config, cli.output, core.privacy.pipeline, providers.dispatcher, core.router.router, core.governance.gateway, and std.str.

G1.6/RG1.8 (2026-10-01): opens the store at config.datadir and passes it to core.router.fallback.dispatchchain with the use case `cli-ask`, so every hop asks the kill switch before it is sent and a store that cannot be opened refuses every hop. Prints the degraded-mode line when a local model answered after a cloud first choice.

F5.3 (2026-10-08): every hop that sends writes its disclosure record. After the privacy run the store is opened, the run's per-layer metrics are recorded (core.audit.hoprecord.recordlayers), and its facts (`hr.factsof`, use case `cli-ask`, selection `user_choice` by `user`) are passed to dispatchchain, which reserves and completes a record per hop sent and audits each refused hop. A run the filter refuses is audited as `privacy_refused`. `--dry-run` sends nothing and writes nothing. Reached from the binary as `loke ask` since F3.9 (cli.main.handleask); before that the command was a stub and nothing called this module.
