Settings management API endpoint. Exports get and post handlers, and respond, the POST body as a testable `$settingsreply` (status and body). A POST body is `{"key":"...","value":"..."}`, both strings; any other shape is 400 before the file is read. API keys (anthropic_api_key, openai_api_key) are stored in the OS keychain via core.storage.keychain.setapikey() and then removed from the JSON file; if the keychain refuses the key the answer is 500 and the file is untouched. Any other key that looks like a credential (`*_api_key`, `*apikey`, or containing secret, token, password or credential) is refused with 400 and never written. Non-secret settings are merged into ~/.loke/settings.json (read, set one key, write; LS1.4a): every other entry is kept as written, where it used to be overwritten by `{key:value}`; a settings file that cannot be read or is not a JSON object is refused with 500 and left as it is. removekeyfromjson likewise keeps every other entry (it used to rebuild the file from four named fields). Writes are not atomic and concurrent POSTs are not serialised: two racing POSTs can lose the earlier key (a lost update), and a POST that reads a half-written file is refused without writing. No response echoes a value. On GET, keys are retrieved from the keychain first, falling back to JSON for migration from plaintext storage. Keys are masked for display (first 4 chars + "****"). Depends on std.http, std.str, std.json, std.file, std, shared.jsonobj, shared.origin and core.storage.keychain.
