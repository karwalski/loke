Degraded mode (RG1.8): a request first routed to a cloud provider that a local model answered because the cloud hops failed or were refused. The local hop itself is core.router.router.degradehop, put at the end of a cloud-first chain by routechain. `isdegraded(first;answering)` says whether an answer was degraded; `marker` gives the reply fields (`"degraded":true,"degraded_from":"<provider:model>"`) and `notice` the line `loke ask` prints. `noteanswer(store;first;answering;cid)` records the provider's disruption so it can be measured against a tolerance: the first degraded answer for a provider writes an audit_log row `degraded_mode_entered` (provider, the local model, the request's correlation id) and keeps the start time in settings (`routing.degraded.<provider>.since`, milliseconds); further degraded answers write nothing more; the next answer from that provider writes `degraded_mode_exited`, whose duration_ms is the length of the disruption, and clears the time. A local first choice is never degraded and never ends a disruption. With no store nothing is recorded. Callers: core.router.fallback.dispatchchain (`loke ask`) and page.api.pipeline.walkchain (the browser request path). Tested by tests/integration/test_degrade_local.tk. Depends on core.router.router, core.storage.settings, core.storage.audit, shared.jsonobj, shared.log, shared.types and std.str.
