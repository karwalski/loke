Dispatches a fallback chain built by core.router.router.routechain (F5.3). The hops are tried in order through core.providers.dispatcher.trydispatch and the first that answers is the answer. Before each hop is sent, rtr.hopallowed is asked again with the sensitivity the router computed (the chain's chainsens, never a caller's) and the router's configuration, so a cloud hop is never sent for RESTRICTED data, nor after a local first choice unless routing.fallback_to_cloud is on. chainattempted lists every hop actually sent, as `provider:model`, and no refused hop, which is how tests/unit/router/test_fallback_chain.tk shows a hop was not tried without contacting a provider. A model the user named (`loke ask --model`) replaces the first hop's id and disables fallback. It records no disclosure row and checks no kill switch: its one caller, the CLI's `loke ask`, does neither for a first choice either, and the browser request path (page.api.pipeline), which does both, does not use it. Depends on core.router.router, core.providers.dispatcher, core.providers.types, shared.types, shared.log and std.str.
