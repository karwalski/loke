Dispatches a fallback chain built by core.router.router.routechain (F5.3). The hops are tried in order through core.providers.dispatcher.trydispatch and the first that answers is the answer. Before each hop is sent, rtr.hopallowed is asked again with the sensitivity the router computed (the chain's chainsens, never a caller's) and the router's configuration, so a cloud hop is never sent for RESTRICTED data, nor after a local first choice unless routing.fallback_to_cloud is on. Then the kill switch is asked for that hop (G1.6): `dispatchchain(store;usecase;...)` refuses a hop when the global switch, the hop's provider or the caller's use case (`cli-ask` for `loke ask`) is switched off, or when the store is 0 or its settings cannot be read (core.governance.killswitch.isblocked fails closed); a refused hop is not sent, is not in chainattempted, and chainfailures names the switch. chainattempted lists every hop actually sent, as `provider:model`, and no refused hop, which is how tests/unit/router/test_fallback_chain.tk and tests/integration/test_kill_switch_paths.tk show a hop was not tried without contacting a provider. A model the user named (`loke ask --model`) replaces the first hop's id and disables fallback. When a local hop answers after a cloud first choice the answer is degraded (RG1.8): chaindegraded is true, chainnotice is the line to print, and core.router.degraded.noteanswer records the provider's disruption. It records no disclosure row; the browser request path (page.api.pipeline), which does, walks the chain itself. Depends on core.router.router, core.router.degraded, core.governance.killswitch, core.providers.dispatcher, core.providers.types, shared.types, shared.log and std.str.
