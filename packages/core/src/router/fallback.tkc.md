Dispatches a fallback chain built by core.router.router.routechain (F5.3). The hops are tried in order and the first that answers is the answer. Before each hop is sent, rtr.hopallowed is asked again with the sensitivity the router computed (the chain's chainsens, never a caller's) and the router's configuration, so a cloud hop is never sent for RESTRICTED data, nor after a local first choice unless routing.fallback_to_cloud is on. Then the kill switch is asked for that hop (G1.6): `dispatchchain(store;usecase;...)` refuses a hop when the global switch, the hop's provider or the caller's use case (`cli-ask` for `loke ask`) is switched off, or when the store is 0 or its settings cannot be read (core.governance.killswitch.isblocked fails closed); a refused hop is not sent, is not in chainattempted, and chainfailures names the switch. chainattempted lists every hop that passed the gate and the kill switch, as `provider:model`, and no refused hop (a hop with no client, or whose record could not be reserved, is listed and sent nothing), which is how tests/unit/router/test_fallback_chain.tk and tests/integration/test_kill_switch_paths.tk show a hop was not tried without contacting a provider. A model the user named (`loke ask --model`) replaces the first hop's id and disables fallback. When a local hop answers after a cloud first choice the answer is degraded (RG1.8): chaindegraded is true, chainnotice is the line to print, and core.router.degraded.noteanswer records the provider's disruption. F5.3 (2026-10-08): every hop that sends has its disclosure record, as on the browser path. `dispatchchain` takes the privacy run's facts (`core.audit.hoprecord.factsof`); for each hop it builds the body with `core.providers.dispatcher.requestbody` (the function the provider's client sends with), reserves the record from it with its `llm_dispatch` audit row (`hr.reserve`), sends exactly that body (`disp.sendbody`), reads it with `disp.replyof`, and completes the record with its outcome audit row (`hr.outcome`). A hop whose record cannot be reserved is not sent; a refused hop is audited (`hr.refused`) with no disclosure row. Each hop has its own correlation id (`hr.hopid`). Depends on core.router.router, core.router.degraded, core.governance.killswitch, core.providers.dispatcher, core.providers.types, core.audit.hoprecord, shared.types, shared.jsonobj, shared.log and std.str. Tested by tests/integration/test_ask_disclosure.tk.
