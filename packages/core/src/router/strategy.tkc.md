The four named router strategies — cheapest-adequate, fastest, best-quality, local-first — added by X8.6, which existed as a claim in docs/claims.md D3 with zero matches for any of the four names anywhere in packages/ or src/. strategyname is the single place the names are spelled, so the claim and the code cannot drift apart again; isstrategyname lets a caller reject a typo and strategyfromname falls back to best-quality, which is the ranking core.models.registry.bestfortask already applied. Comparison goes through strategyrank because `==` on two sums compares the handle and a returned sum does not compare equal to an identically constructed local (T-14). bestbystrategy walks reg.findfortask's candidates and returns a plain $modelcapability with reg.nocapability() as the sentinel — an array of structs crosses a module boundary intact, f64 fields included, probed this session, and maxcostper1k is an f64 parameter, which also crosses intact where a bare f64 return would not (T-20). It applies reg.meetstier, honours the caller's maxcostper1k for the first time — $selectioncriteria has always carried it and bestfortask never read it — and applies a quality floor to cheapest-adequate alone, because that is the only strategy whose objective would otherwise reward the worst model available. The cost table here is the third copy of those numbers in the repository, deliberately: T-20 means a shared f64 accessor could not be called across a module boundary. The adequacy floor of 0.70 is a policy choice, and the registry's qualityscore and speedtoks are unmeasured editorial estimates, both stated as such in the source rather than implied away. A strategy chooses between permitted models and can never widen what is permitted: the RESTRICTED gate lives in core.router.selector.selectmodelwith, ahead of any strategy, and core.router.router.routerequest re-checks it. Depends on core.models.registry, shared.types, std.str and shared.log.
