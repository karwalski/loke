The toke side of the VM1.1 numeric result sink (VM1.6). `write(m;path)` validates a `$measurement` and appends it as one JSON line in the schema of `benchmarks/lib/result.py`, with keys sorted as `result.write` emits them, so `result.read_all` reads rows from both sinks. It refuses what `result.validate` refuses (no metric, units or workload; n below 1; a token-denominated metric without a tokenizer; a model without a pinned version) plus a value that is not a finite number, and a refused measurement writes nothing. The value is carried as a string because an f64 returned across a module boundary is corrupted (T-20). The toke, ooke and loke commit fields are written null: a running binary does not know them, and a guessed commit would be unreproducible. Depends on std.str, std.file, std.json and std.sys. Tested by `tests/unit/eval/test_resultsink.tk`.
