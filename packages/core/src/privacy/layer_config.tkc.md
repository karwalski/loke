Privacy layer configuration (F3b.2). Reads the `[[privacy.layers]]` entries of a config.toml text line by line (std.toml has no array-of-tables accessor) and `resolve` applies them to a `core.privacy.filterregistry`: `id`, `enabled`, `priority` (lower runs first; the registry is sorted stably), `mode` (detect-and-mask, detect-only, veto), `confidence_threshold` (0..1) and `entity_filter` (types the layer declares in `core.privacy.entityvocab`). Any malformed entry returns an error and the registry unchanged; `core.privacy.pipeline` then refuses every run. The regex layer cannot be disabled, made detect-only, thresholded or filtered from config: those are warned about and not applied. At run time `accepted` filters a layer's detections by its threshold and entity filter, `masks` says whether they are masked and `vetoes` whether a veto layer refuses the run. Depends on `std.str`, `shared.types`, `core.privacy.filterregistry`, `core.privacy.entityvocab`. F3b.16: resolve also returns shared.config.privacyerror(text) as its error, so a [privacy] consensus_threshold or privacy_filter_threshold that is set and unusable refuses every run made with the config. F3b.17: that error carries its own `[privacy] in config.toml cannot be applied:` prefix (`privacyheader`), and `refusal(error)` words the refusal for any resolve error, adding the `privacy.layers` prefix only to a `[[privacy.layers]]` error; `core.privacy.pipeline` and `core.privacy.comparison` use it.
