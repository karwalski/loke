The preset catalogue the governance UI shows (RG1.9), derived from `core.policy.presets.registry` at run time so it cannot drift from it. `registryviews()` returns one `$presetview` (id, `$policy`, jurisdiction, rules) per name in `registry.names()`; `catalogjson(views)` renders any list of views as the JSON moke's `/api/presets` serves; `registryjson()` is the two together.

`rulestatus(description)` classifies a rule by the class its description opens with, the convention the APRA presets (RG1.1, RG1.2) and the AU Privacy preset use: `EVALUABLE` gives `evaluable`, `DOCUMENTATION ONLY` gives `documentation`, `UNIMPLEMENTED` or `NOT IMPLEMENTED` gives `unimplemented`, and anything else `unclassified` (the older presets state the law, not what loke does about it). There is no `enforced` status: nothing on the request path calls `core.policy.loader.evaluate` (RG1.1), which `enforcedonrequestpath()` (false) and `enforcementnote()` state in the JSON so the page can say so. Depends on std.str, core.policy.schema, core.policy.types, core.policy.presets.registry and shared.jsonobj (for `escape`).
