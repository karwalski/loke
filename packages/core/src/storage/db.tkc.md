Core database module. Opens the SQLite database at the configured data directory, runs all pending schema migrations, and exposes a `$store` handle.

Database-level encryption is NOT available and the module says so through a predicate rather than a claim: the toolchain links plain SQLite, which accepts `PRAGMA key` and ignores it, so the former encryption step was removed under X8.1 instead of repaired. `dbencryptionavailable()` and `dbencryptionstatus()` are the single source everything asserting encryption reads, and they flip on their own if the toolchain ever gains SQLCipher. The 32-byte secret comes from the OS keychain and nowhere else (X8.3): `ensuredbkey` uses a stored secret, generates and stores one only when no item exists, and returns "" — refusing, not replacing — when an item exists but does not read back as 64 characters (`dbkeyaction` is that decision as a pure function). There is no environment or file fallback; `dbkeyfromenv` was deleted. `openstore` does not read the key. The one consumer is the sealed placeholder mapping (X8.2, `core.privacy.placeholderstore`).2.

Also holds the typed row accessors (`rowstr`, `rowi64`, `rowi32`, `rowbool`, `rowf64hundredths`) that a `$row` must be read with, money formatting from exact integer hundredths, schema introspection (`tableexists`, `triggerexists`, `auditappendonlyenforced`) for code that needs to assert its schema rather than infer it from an empty query, and the reporting-window conversion (`msrangeof`, `daysagoms`, `createdatwindowclause`) that turns ISO dates into the epoch milliseconds `audit_log.created_at` is stored in. Depends on std.db, std.str, std.env, std.crypto, shared.log, shared.types, core.storage.keychain and core.storage.migrations.
