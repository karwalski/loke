Budget enforcement and tracking. Creates budget managers with configurable daily/monthly token and cost limits, checks whether a request fits within all active budget periods (warning when thresholds are approached), records actual token and cost usage after requests, resets usage for a given period, and formats current usage as a human-readable summary. Exports new, defaultlimits, periodlabel, check, record, resetperiod, and formatusage. Depends on shared.types, std.str, shared.log, and core.optimiser.budgettypes. GA1.5: record did nothing at all — its whole body was `manager.usage.get(i)==$budgetusage{...}`, a comparison whose bool was discarded (T-26), so no usage row was ever updated and a budget that never accumulates never refuses. It returns the updated manager now, because toke structs are values. rowtokens and rowcostmicrousd are per-ROW accessors and deliberately not totals: defaultlimits has one row per period and both count the same spend, so a total would double-count. Cost crosses as millionths of a dollar, not shared.types.f64hundredths, because hundredths of a dollar are cents and a request costing a fraction of a cent would record as zero. withusage seeds the counters from values a caller persisted, which is what lets a budget survive the process that spent it. new no longer uses str.arraylen/str.arrayget. page.api.pipeline is the first importer.
