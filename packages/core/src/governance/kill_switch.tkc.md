Implements the kill switch that blocks all LLM traffic when engaged. Supports auto-release after a configurable timeout, persists state to settings store, and provides a text-based widget for the dashboard. Depends on shared.types, core.storage.db, core.storage.settings, std.str, and shared.log.

G1.6 adds per-use-case and per-agent scope beside the global and per-provider switches: `engageusecase`/`releaseusecase`/`isusecaseblocked` for the use cases a request path passes (today only `browser-chat`), and `engageagent`/`releaseagent`/`isagentblocked` for any well-formed agent id. Each is one flag in the settings table, so it persists across restarts. Scoped reads fail closed: no store, or a settings table that cannot be read, means blocked. `isblocked(store;provider;usecase)` is the global, provider or use-case switch, and `blockedscope` names which; `refusalmessage` and `agentrefusalmessage` are the messages a refused caller returns. Every engage and release, global included, writes an `audit_log` row (`kill_switch_engaged` / `kill_switch_released`, scope and target in `correlation_id`), and a refusal is audited by its own writer (GA5.32): `recordrefusedrequest` writes `kill_switch_refused` keyed on the request id, `recordrefusedagent` writes `kill_switch_agent_refused` (`agent:<id>`), and a refused change (an unknown use case or provider, a malformed agent id) writes `kill_switch_change_refused` with `<scope>:unrecognised`, never the target typed. Also depends on core.storage.audit and std.db.

2026-10-01 (G1.6): the use cases are `browser-chat`, `cli-ask`, `cli-proxy` and `no-custody`, each passed by a request path. `globalblocked(store)` is the global switch read for a gate: engaged, no store, or a settings table that cannot be read; `blockedscope` uses it, and reads the provider flag fail closed too, so `isblocked` is fail closed in every scope (before, an unreadable global or provider flag read as off).
