Implements the kill switch that blocks all LLM traffic when engaged. Supports auto-release after a configurable timeout, persists state to settings store, and provides a text-based widget for the dashboard. Depends on shared.types, core.storage.db, core.storage.settings, std.str, and shared.log.

G1.6 adds per-use-case and per-agent scope beside the global and per-provider switches: `engageusecase`/`releaseusecase`/`isusecaseblocked` for the use cases a request path passes (today only `browser-chat`), and `engageagent`/`releaseagent`/`isagentblocked` for any well-formed agent id. Each is one flag in the settings table, so it persists across restarts. Scoped reads fail closed: no store, or a settings table that cannot be read, means blocked. `isblocked(store;provider;usecase)` is the global, provider or use-case switch, and `blockedscope` names which; `refusalmessage` and `agentrefusalmessage` are the messages a refused caller returns. Every engage and release, global included, writes an `audit_log` row (`kill_switch_engaged` / `kill_switch_released`, scope and target in `correlation_id`), and `recordrefusal` writes `kill_switch_refused` for callers with no audit row of their own. Also depends on core.storage.audit and std.db.
