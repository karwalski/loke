Generates a periodic governance report — request counts, policy violations, quota breaches, top triggered rules — as markdown, and writes it to the filesystem. All four queries used to read `audit_events`, a table no migration creates; they read `audit_log` now with `ts` mapped to `created_at` (GA5.12). The request path writes `policy_deny` and `quota_exceeded` (GA5.19) and `policy_require_approval` when it holds a request for approval or refuses a presented approval (GA5.26), so those counts are measured from those dates. `audit_log` has no rule identifier, so the top-triggered-rules section cannot be computed and says so. `fromts`/`tots` are epoch milliseconds, matching `created_at`. Depends on std.db, std.str, std.fs, shared.log, std.time and core.storage.db.
