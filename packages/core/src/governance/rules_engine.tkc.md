Evaluates compound governance rules (AND/OR/NOT logic) against an evaluation context containing sensitivity, model tier, request count, hour, and scope. Supports rate limiting with SQLite-backed event tracking. Provides default rules for high-sensitivity cloud routing, burst throttling, off-hours premium use, and confidential-external scope denial. `presetrules(name)` derives compound rules from a built-in policy preset, and derives only the two settings `$evalcontext` can actually express: `requireapprovalabove` becomes a sensitivity threshold, and `crossborderallowed: false` becomes a prohibition on the external scope — the same field and value the built-in `default-confidential-external-scope` rule uses. Nothing else is synthesised. A preset's per-entity anonymisation actions, blocked entity types, retention periods and provider permissions have no `$condition` field to match on and are enforced through `core.policy.loader.evaluate` against the preset's own rule list instead; do not add conditions for them by inventing fields. The approval rule's action is `approve`, outside the allow/warn/throttle/deny vocabulary the built-in rules use: `evaluate` copies the action through verbatim and this module has no importers, so nothing is misled, and downgrading it to `warn` would make the preset's control quietly weaker than the preset says it is. Depends on std.str, std.db, shared.log, std.time, std.json, core.storage.db and core.policy.presets.registry.
