Implements Data Subject Access Request workflows for GDPR compliance: submit, process access exports (a JSON file of the subject's data across tables), process erasure, and status tracking. Each table is asserted to exist through `core.storage.db.tableexists` before it is read or cleared, so "we hold nothing about you" and "we did not look" are no longer both rendered as `[]` (GA5.12). Two deliberate positions are recorded in the code: the audit trail cannot be exported per subject because `audit_log` carries a request correlation id and no user identifier, so the export carries the key with an empty array and an adjacent note explaining why; and the audit trail is not erased, because it is append-only (GA5.9) and records no personal data to erase. Depends on std.db, std.str, std.fs, shared.log, std.time, std.json and core.storage.db.
