Provider dispatcher that routes completion requests to the appropriate backend (Anthropic, OpenAI, or Ollama) based on the selected provider. Also provides a guardian-aware dispatch variant that prepends the loke privacy guardian system prompt. Depends on shared.types, core.providers.types, core.providers.anthropic, core.providers.openai, core.providers.ollamaprovider, shared.log, and std.str. LS1.1j added the trydispatch* family — trydispatchanthropic, trydispatchopenai, trydispatchollama, trydispatchlocal, trydispatchunsupported, trydispatch and trydispatchwithguardian — which return a plain $completionresponse instead of a result. A caller tests the outcome with isdispatched and reads the failure message with dispatcherror, because a function returning $completionresponse!$lokeerr cannot report its outcome under T-18 and reading a field off the mis-bound value segfaults. The result-returning dispatch* functions (dispatch, dispatchwithguardian, dispatchanthropic, dispatchopenai, dispatchollama, dispatchlocal, dispatchunsupported and aserror) were removed on 2026-09-27 once packages/cli ask and proxy moved to trydispatch; no caller remains. guardedrequest builds the guardian-prepended request and is shared by both forms.

F5.3 (2026-10-08): the dispatch in two steps, for a caller that must record the exact octets it sends (core.router.fallback). `requestbody(req;provider)` builds the body with the same function the provider's client sends (core.models.ollama.chatbody, core.providers.types.anthropicbody, core.providers.openai.requestbody), "" for a provider with no client; `sendbody(d;provider;body)` sends that string to the endpoint and transport the client uses; `replyof(provider;raw;modelid)` reads the answer with the client's parser, a missing or empty answer being a failure, with Ollama's prompt_eval_count and eval_count kept. `endpointhost` and `islocal` name the destination for the record.
